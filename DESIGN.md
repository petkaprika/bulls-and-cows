# DESIGN.md — Bulls and Cows game

## 1. Структуры данных

Для хранения настроек используется интерфейс `GameSettings` (`src/types/GameSettings.ts`). Он содержит систему счисления и длину секретного числа.

Состояние игры описано интерфейсом `GameState` (`src/types/GameState.ts`). Оно включает настройки, секретное число и историю попыток.

Каждая попытка хранится в виде объекта `GuessHistoryEntry` с тремя свойствами:

- `guess` — введённая комбинация;
- `bulls` — количество цифр на правильных позициях;
- `cows` — количество угаданных цифр на неправильных позициях.

Секретное число хранится в виде строки, чтобы сохранять ведущие нули, например `0123`.

В проекте также используются:

- `Array` — для хранения истории попыток и цифр;
- `Set` — для проверки уникальности цифр;
- `Map` — для кэширования результатов вычислений;
- `BASE_VALUES` (`src/constants.ts`) — для хранения числовых оснований систем счисления.

При обновлении истории создаётся новый массив с помощью spread-оператора без изменения предыдущего состояния.

## 2. Алгоритмы

### generateSecret (`src/logic/generateSecret.ts`)

Генерирует секретное число заданной длины. Цифры выбираются случайным образом. Повторяющиеся цифры отбрасываются. Функция принимает генератор случайных чисел параметром, что позволяет использовать предсказуемые значения в тестах.

### evaluateGuess (`src/logic/evaluateGuess.ts`)

Сравнивает попытку с секретным числом и подсчитывает быков и коров. Для подсчёта используются методы массивов `reduce()`, `includes()` и `indexOf()`.

### isValidGuess (`src/logic/isValidGuess.ts`)

Проверяет длину комбинации, допустимость символов и отсутствие повторяющихся цифр. Для проверки уникальности используется `Set`, для проверки всех символов — `every()`.

### createDigitValidator (`src/logic/createDigitValidator.ts`)

Принимает основание системы счисления и возвращает функцию для проверки отдельной цифры. Это пример каррирования. Валидатор используется как в `isValidGuess`, так и при вводе символов в игровом поле.

### countPossibleSecrets (`src/logic/countPossibleSecrets.ts`)

Рекурсивно вычисляет количество возможных секретных чисел без повторения цифр. Результаты сохраняются в `Map`, чтобы не выполнять повторные вычисления. Используется формула количества размещений:

`P(base, length) = base! / (base - length)!`

Ведущие нули разрешены.

## 3. Сложность алгоритмов (Big O)

Временная сложность показывает, как растёт количество операций при увеличении входных данных. Пространственная сложность показывает, сколько дополнительной памяти требуется алгоритму.

Обозначения:

- `n` — длина числа или попытки;
- `b` — основание системы счисления.

| Функция                | Временная сложность                                 | Пространственная сложность |
| ---------------------- | --------------------------------------------------- | -------------------------- |
| `generateSecret`       | Зависит от `n` и `b` из-за повторной генерации цифр | O(n)                       |
| `evaluateGuess`        | O(n²)                                               | O(n)                       |
| `isValidGuess`         | O(n) в среднем                                      | O(n)                       |
| `countPossibleSecrets` | O(n) при новом вычислении, O(1) при попадании в кэш | O(n)                       |

**Пояснения:**

- `generateSecret`: при генерации могут встречаться повторяющиеся цифры, которые приходится отбрасывать. Для проверки используется `includes()`. Поэтому время зависит от длины числа и основания системы.
- `evaluateGuess`: для каждой цифры выполняется поиск в секретном числе, поэтому получается O(n²).
- `isValidGuess`: каждый символ проверяется один раз, а поиск повторов выполняется с помощью `Set`.
- `countPossibleSecrets`: рекурсия выполняется по длине числа, а мемоизация позволяет не повторять уже выполненные вычисления.

## 4. Принципы Clean Code

В проекте применены следующие принципы:

**Разделение ответственности.** Игровая логика находится в `src/logic/`, типы — в `src/types/`, пользовательский интерфейс — в `src/ui/`.

**Единственная ответственность.** Каждая функция выполняет одну конкретную задачу. Например, `generateSecret` генерирует число, а `evaluateGuess` проверяет попытку.

**Понятные имена.** Названия функций и переменных отражают их назначение: `isValidGuess`, `generateSecret`, `gameState`, `historyList`.

**DRY (Don't Repeat Yourself).** Проверка цифр реализована в `createDigitValidator` и повторно используется в разных частях приложения. Числовые основания хранятся в одном объекте `BASE_VALUES`.

**Иммутабельность.** История попыток обновляется созданием нового массива, а не изменением существующего через `push()`.

**Функции высшего порядка.** Используются методы массивов `reduce()`, `filter()`, `every()` и `some()`.

**Каррирование.** `createDigitValidator` возвращает функцию проверки цифры для выбранной системы счисления.

**Мемоизация.** `countPossibleSecrets` использует `Map` для хранения результатов предыдущих вычислений.

**Типизация.** Интерфейсы `GameSettings`, `GameState` и `GuessHistoryEntry` определяют структуру данных и помогают обнаруживать ошибки типов.

**Безопасная работа с DOM.** Элементы создаются через `document.createElement()`, содержимое задаётся с помощью `textContent`. `innerHTML` и `insertAdjacentHTML` не используются.
